# Монтаж через GPT / Codex

Основной процесс и роли GPT — [docs/GPT-МОНТАЖ.md](../../../docs/GPT-МОНТАЖ.md).
Локально работают скрипты монтажа и рендера; GPT выбирает содержание и принимает решения.

## Начало работы

1. Определи ролик и проект: `scripts/projects.py where <имя>`; прочитай свежие `rules.md` проекта и раздела,
   `DESIGN.md` проекта и бриф (`scripts/styles.py --brief <имя>`). Правила проекта важнее стиля.
2. Посмотри состояние в `work/<имя>/`: edit.json, score.json, plan.md, director.json, page.py, approved.json,
   timeline.json. Ручные правки timeline.json не затирай. Принятый выпуск меняй только по просьбе.
3. Один ролик — одна сессия. «Смонтируй новые» — запускай `scripts/batch.py`, а не монтируй всю пачку здесь.
4. Новому проекту нужна заполненная анкета (`projects.py ready <проект>`). Без неё назови недостающие ответы.
   На новой машине проекты пустые; личное умолчание — projects/.default, не обязательно Антишкола.

## Выбери режим

- **Автопилот** — `scripts/autopilot.py <имя>`: GPT-аналитик → score.json → сборка без ИИ → критик по листу кадров
  → рендер. Для пачки — `scripts/batch.py`. Сначала прочитай в [справочнике](references/workflows.md) разделы
  «Автопилот» и «Дизайн-система проекта». Правь партитуру, затем `scripts/score.py <имя>`; не index.html.
- **Режиссёрская сессия** — нестандартный монтаж, новые клипы Flow, варианты A/B и сложные правки: прочитай
  «Основной конвейер» и «Порядок работы режиссёра» в справочнике. Используй Montage, не переписывай сборку.
- **Сборка из нескольких видео** — раздел «Сборка: один ролик из нескольких видео»: pack.json, затем обычный процесс.
- **Быстрый монтаж без графики** — разделы справочника начиная с «Быстрый конвейер»: scripts/reels.py.
- **Футажи** — скилл flow; **числа, карты, формулы** — скилл viz. Их инструкции нужны только при таких вставках.
- **Ручная правка в студии, Windows, A/B, шрифты, длинный урок** — одноимённый раздел справочника по месту.

Не загружай справочник целиком. Найди нужный заголовок и прочитай связанный фрагмент. Сигнатуры API — docstring
нужного скрипта, тайминги слов — `scripts/words.py`, а не чтение всех исходников и чужих page.py.

## Дизайн и анимации

- Палитра, роли шрифтов, компоненты и движения — `projects/<проект>/DESIGN.md`; система применяется design.py.
  Новый проект начинает с presets/templates, затем получает свой бренд. Не копируй стиль другого клиента.
- Геометрия формата и безопасные зоны — scripts/formats.py; в вертикали серая зона справа и снизу строже общего
  отступа SAFE. Надписи и субтитры не закрывают лицо. Детали и готовые приёмы —
  [docs/ГРАФИКА.md](../../../docs/ГРАФИКА.md).
- Готовые движения — kit, design, Montage, fx, viz и blueprint; в партитуре выбирай kind, слова, раскладку и время.
  Не пиши заново вход/выход, маркер, счётчик или переход, который уже есть в библиотеке.
- **Каждый ролик — своя идея.** До плана придумай concept (идея, мотив, хук) из содержания и сверь с недавними
  роликами проекта. Шаблон задаёт качество исполнения. Хук и композиция этой истории — новые; score.novelty
  проверяет повторение. Своя scene использует готовые enter/leave/slam/draw и токены DESIGN.md.
- Все правки человека собирай в один список и применяй вместе. Механические изменения — скриптами без ИИ;
  автоматическая доводка по провалам — роль repair. Если её результат не проходит проверку, автопилот вернётся
  к основной роли. Модель не выбирается по названию Sonnet/Haiku: роли — presets/gpt.json.

## Очередь и проверка

Тяжёлое (transcribe, pack --build, prep, track, matte, reframe, render_reel, reels.py) из студии — только через
`scripts/jobqueue.py add <NN>-<имя> "python scripts/…"`. Один тяжёлый процесс на машине; ждём через
`jobqueue.py wait <задача>`. Маска — после страницы, только по её окнам. Подробности и ловушки — справочник.

До рендера: партитура/план проходит проверку, compose, verify_page, осмотр ключевых кадров. Потом render_reel
и проверка файла. Проектные ограничения AGENTS.md (память, сетка кадров, рез по тишине, уборка в finally) обязательны.
Браузер для Flow используй только если Computer Use реально доступен в запуске Codex; если его нет — сообщи до
рендера и сохрани бриф, не подменяй заказ молча.

Из студии отвечай коротко: что сделано, где файл и что осталось. В пачке в конце —
`СТАТУС: ГОТОВО / ЖДУ ОЧЕРЕДЬ / НУЖЕН ЧЕЛОВЕК — …`. Дописанные во время хода просьбы студия передаст одним
следующим запросом. Большой разговор продолжится свежей сессией с передачей дел; состояние — в файлах ролика.
