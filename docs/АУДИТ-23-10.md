## 1. Логика выборки дизайн-систем

### Как сейчас

`templates.score`: мешок слов. Подстроки из `signals.about` ищутся в ответах анкеты, вес «о чём» ×3, остальное ×1,
тон ×2. «Сборка» +3 (только для pack), «звук автора» ±4. Порог 3 очка — одно совпавшее слово. Анкета сохранена, а
шаблона нет → `apply` ставит лучший сам.

### Что не так (прогон 23.10 на придуманных анкетах)

| Анкета | Выбрано | Должно быть | Причина |
|---|---|---|---|
| «Психолог: про тревогу и выгорание, советы» | testimonial (5) | эксперт | «психолог» — в признаках отзыва |
| «Влог про путешествия, говорю в камеру» | brand-lifestyle (3, ставится сам) | эксперт/своё | шаблон сборки (pack, Хормози) не штрафуется для говорящей головы |
| «Учу английскому, разбираю ошибки» | своё (2) | expert-viral | «учу» ≠ «учител», одно слово «разбор» не набирает порог |
| «Стоматолог…, звук: без музыки» | lyric +1 | — | «музык» в отрицании засчитывается |
| «Маркетолог, кейсы клиентов» | expert-premium 8 / testimonial 5 | ок, но отрыв мал | «клиент» общий для двух жанров |

Ещё дефекты:
1. **Смена шаблона почти ничего не меняет.** Второй `apply` не трогает `brief.style` (условие `not config.get("template")`),
   не трогает умолчания, уже записанные прошлым шаблоном (ключ уже есть), и не меняет DESIGN.md («у проекта своя»,
   хотя это DESIGN.md прошлого шаблона). Меняется только блок в rules.md. Агент читает одно, сборка делает другое.
2. **Первый apply перезаписывает стиль, выбранный человеком**, если шаблона ещё не было. Это противоречит
   «заданное руками не трогает».
3. **Ничья решается алфавитом** (`sorted` стабилен, первым идёт brand-lifestyle).
4. **Проверка подбора переобучена.** selfcheck проверяет, что анкета каждого эталона узнаёт свой шаблон. Признаки
   писались под эти же анкеты, поэтому проверка не может покраснеть на новом жанре.
5. **Шаблон склеивает почерк и бренд.** DESIGN.md шаблона — это цвета и шрифты чужого клиента (красный лак Антишколы,
   кирпич Виктории). Новый клиент стартует в чужом фирменном стиле. Это против правила «общее у проекта — только
   узнаваемость своего бренда».
6. **Эталонных видео нет в git** (все 5 в `output/`). У друга блок «посмотри эталон до плана» указывает на
   несуществующий файл, а `templates.py sheets` на его машине не соберёт лист. Лист кадров `exemplar.jpg` в git есть
   — его и надо называть главным.
7. Шаблон — на весь проект, а тип монтажа — у раздела (`talking`/`pack`). В проекте с разделом-сборкой и разделом
   «говорящая голова» один шаблон не подходит обоим.
8. Мелочь: Montage пишет «дизайн-система: projects/slavamontazh/viktoriya-topolskaya/DESIGN.md», а файл лежит
   у проекта (`projects/slavamontazh/DESIGN.md`). Брать путь у `self.design.path`.

### Как предлагаю

**Дерево вместо мешка слов.** Сначала твёрдые факты, потом слова — как решил бы человек:

```
1. keep_audio (поёт под свой трек)             → lyric
2. раздел/проект kind = pack (несколько клипов) → brand-lifestyle
3. говорит не автор, а его клиент (отзыв)       → testimonial
      признак — фраза про отзыв/благодарность/«клиент рассказывает», а не профессия
4. иначе — эксперт в кадре. Ветка по тону:
      динамичный / дерзкий / с юмором           → expert-viral
      спокойный / премиальный / продающий       → expert-premium
      тон не задан — по словам «о чём» (обучение → viral, услуги и кейсы → premium)
```

- Шаблон с другим `kind`, чем у раздела, не кандидат вообще (а не 0 очков).
- Слова в отрицании («без музыки», «не поём») не считаются: окно 2 слова после «без/не/нет».
- Уверенность — по отрыву первого от второго, а не по абсолютному порогу. Отрыв мал → шаблон не ставится сам,
  в анкете два варианта с причинами и листами кадров, выбирает человек.
- «Своё» — только по выбору человека. Иначе у эксперта всегда есть разумное умолчание ветки, с пометкой «по умолчанию».

**Почерк отдельно от бренда.**
- Шаблон несёт почерк: стиль, умолчания, уроки, структуру DESIGN.md (роли шрифтов, приёмы, движения).
- Бренд — из анкеты (`brand`: цвета, шрифты) и проекта. При `apply` DESIGN.md собирается так: скелет шаблона +
  цвета/шрифты из ответа `brand`. Не названы — открытые шрифты шаблона и нейтральная палитра с пометкой
  «бренд не задан — спроси человека». Шрифт, которого нет в `presets/fonts`, — громкий отказ с подсказкой
  положить файл, а не молча чужой.

**Смена шаблона честная.**
- `project.json → template_set`: какие ключи записал шаблон.
- При смене они заменяются значениями нового шаблона. Ключи, которые человек ставил сам, остаются.
- DESIGN.md заменяется, если совпадает (по хэшу) с DESIGN.md прошлого шаблона. Если человек его правил — остаётся,
  и студия говорит об этом прямо.

**Шаблон у раздела.** Поле `template` и в `section.json` (раздел уточняет проект, как с правилами). Подбор по
`kind` раздела.

**Проверки, которые умеют краснеть** (selfcheck):
- Набор анкет-ловушек с ожидаемым ответом: психолог-эксперт ≠ testimonial, влог-разговор ≠ pack-шаблон,
  «без музыки» ≠ lyric, репетитор английского → expert-viral, маленький отрыв → не ставится сам.
- Смена A→B меняет стиль и умолчания, не трогает поставленное руками.
- Шрифт шаблона не из git → красный.
- Сломать дерево (убрать шаг «kind») → набор ловушек краснеет.

Можно позже подключить ИИ. Если дерево сомневается (малый отрыв), один короткий ход аналитика по анкете и каталогу
шаблонов. Сейчас не нужно: дерево объяснимо и бесплатно.

## 2. Windows

**Покрыто CI** (каждый push, чистая Windows, кириллица в пути, Git без symlink, CRLF): установка через
`1 Установка — Windows.bat`, оба окружения (`.venv`, `.venv-manim`), модели, ссылки на скиллы, 157 проверок
самопроверки, «после установки git чистый».

**Не покрыто — проверить руками у друга при первом запуске:**
1. **Вход в Claude/Codex** из студии (кнопка «ИИ»). Подписки у друга свои; Flow и Codex-картинки Валеры у него
   не работают, и не должны.
2. **Полный рендер ролика** (`render_reel.py`, `selfcheck --long`) — в CI не гоняется. Предлагаю добавить в CI
   ночной/ручной прогон `--long` (`workflow_dispatch`).
3. **Скорость на процессоре.**
   - faster-whisper на CPU (int8) заметно медленнее mlx на Mac. CUDA подхватится сама, если у друга NVIDIA.
   - BiRefNet на CPU: на Mac ~15 мин на минуту окон, на Windows без GPU — в разы дольше. Порог «дольше 5 мин —
     спросить» (инвариант 6) сработает, это ожидаемо.
   - Друг должен знать: маска нужна только стилям с текстом за спиной.
4. **Шрифты заказчиц.** `make_fonts.py` Виктории качает SF Pro как .dmg — на Windows не соберётся. Проект
   `slavamontazh` у друга не смонтируется. Ожидаемо: шрифты не OFL. Сказать прямо, а не ловить ошибкой.

**Мелкие риски в коде:**
- `jobqueue.run_job`: задача `.sh` идёт через `/bin/bash` — на Windows упадёт. Сейчас `.sh` никто не кладёт.
  Надо отказать громко «задачи — JSON», а не падать на bash.
- Шаги очереди режутся `shlex.split` в POSIX-режиме. Путь с обратными слэшами (`work\IMG_1\aroll.mp4`) от агента
  на Windows потеряет слэши. Надо отказывать громко или нормализовать до `/`. Проверка: шаг с `\` → понятная ошибка.

## 3. Раскатка на друга: конфликты

1. **Чужие клиенты в репозитории.** В git — анкеты, правила и транскрипты (`work/*.txt`) роликов Виктории, Ольги,
   «Вкудесника», Насти, Фирузы. Видео в git нет, но тексты речи и правила с цитатами есть. Это решение Валеры:
   - (а) друг — соавтор того же репо: видит всё и пушит в общий `main`;
   - (б) отдельная копия без `projects/<клиенты>` и их `work/` — чистая база;
   - (в) общий движок, а клиенты — в приватных подпапках (больше работы).
2. **Проект по умолчанию — `antishkola` (ролики Валеры).** Видео, брошенное в корневой `input/`, смонтируется
   с правилами Валеры, лицом бренда и плашкой «смотри у меня в профиле» (про профиль Валеры).
   - Первым делом другу — свой проект через анкету.
   - Лучше: на свежей установке без `projects/antishkola/input/*` студия просит выбрать проект, а не молча
     кладёт в Антишколу.
3. **Если общий `main` (вариант а):**
   - два человека и два агента пушат в одну ветку, Windows-CI на каждый push;
   - `timeline.json` и `approved.json` у каждого свои;
   - договориться: свои ролики — свои проекты/разделы, общие `scripts/` — через PR или с предупреждением;
   - память Claude у друга пустая — правила только из репо (так и задумано, AGENTS.md).
4. **Подписки и бюджеты Валеры.** `footage_budget`, Flow, Codex-картинки, фонотека YouTube через его VPN — про
   его аккаунты. У проектов друга этих умолчаний нет, и хорошо. В onboarding сказать: Flow — только со своей
   подпиской и по его решению.
5. **Онбординг одним листом** — `docs/СТАРТ-ДЛЯ-ДРУГА.md`: установка, вход в ИИ, свой проект через анкету,
   что не будет работать (шрифты заказчиц, Flow) и куда смотреть, если самопроверка красная.
