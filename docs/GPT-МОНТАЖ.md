# Монтаж через GPT / Codex — 10.11.2026

Монтажный агент — GPT через Codex CLI. Студия, пачка, аналитик и критик больше не запускают Claude.
Локальные распознавание, камера, маска, сборка и рендер работают прежними скриптами на Mac и Windows.
Новые зависимости Python и отдельный API-клиент для монтажа не нужны.

## Установка и вход

`npm install -g @openai/codex`, затем `codex login` с собственным ChatGPT. Node.js уже устанавливается с движком.
Те же действия доступны в студии: кнопка «ИИ» → GPT / Codex. Подписка должна давать доступ к выбранной модели;
CLI также поддерживает собственный API-ключ, у которого отдельная оплата. Не переносим чужие ключи и аккаунты.

Запуск студии — `2 Монтаж — Mac.command` / `2 Монтаж — Windows.bat` или `codex` в папке проекта.
Codex читает AGENTS.md и .agents/skills напрямую. Настройка Claude и его расширение больше не нужны.

## Как идёт ролик

1. **Бриф и дизайн проекта.** Прочитать свежие rules.md проекта и раздела, DESIGN.md, бриф и состояние ролика.
   Новый проект проходит анкету и получает подходящий стартовый шаблон; бренд уточняется один раз на проект.
2. **Локальная подготовка.** Речь, события, чистовой дубль и камера. Тяжёлые шаги — строго одной очередью.
3. **Решение GPT.** Аналитик получает компактный пакет: слова с номерами, события, принятые материалы, правила,
   дизайн и недавние идеи. Возвращает score.json. Не пишет заново движок и стандартные анимации.
4. **Сборка и проверки без ИИ.** score → Montage → страница. Машина исправляет механику и отдаёт оставшиеся
   ошибки одним списком с местом и причиной. Поломка сборщика останавливает процесс, а не тратит ходы на партитуру.
5. **Доводка.** Второй ход — дешёвая роль repair, в той же сессии ролика. Если проверка снова красная, третий ход —
   основная роль analyst. Число попыток ограничено; неудача остаётся слышной.
6. **Критик и рендер.** GPT получает партитуру и приложенный лист кадров именно этого ролика. Общего sheet.png
   между роликами нет. После проверки — маска по окнам, рендер и проверка файла.

Автопилот: `scripts/autopilot.py <имя>`; пачка: `scripts/batch.py`. Один ролик — одна сессия, тяжёлое — по одному.
Режиссёрская сессия нужна для необычной сборки, A/B и новых клипов Flow. Google Flow остаётся отдельным способом
генерации, а не поставщиком монтажного агента. Наличие Computer Use проверяется в конкретном запуске Codex;
если его нет, агент сообщает об этом до рендера. Автопилот использует уже принятые клипы.

## Модели по ролям

Единственный источник настроек — `presets/gpt.json`:

- director, analyst, critic: `gpt-6.1-sol`, усилие `high` — идея, сложные решения и зрительная проверка;
- repair: `gpt-6-luna`, усилие `medium` — исправления по общему списку с обязательной повторной проверкой.

Переопределение на машине: `REELS_GPT_ANALYST_MODEL`, `REELS_GPT_ANALYST_EFFORT` и аналогично для остальных ролей.
Старые REELS_BRAIN_MODEL / EFFORT поддержаны только для режиссёра, значение модели должно быть gpt-*.
Ошибка доступа не переключает поставщика и не выбирает другую модель молча. Подбираем роли по качеству принятого
ролика и реальному расходу; экономия на Luna — рабочая гипотеза, не доказательство равного качества режиссуры.

Короткие роли запускаются вне проекта с `--ignore-user-config`, read-only и без загрузки проектных инструкций.
Вместо общих инструкций программиста — компактный `presets/gpt-editor.md` через model_instructions_file.
Все материалы и инструкции передаются явно, запрос — через stdin, лист кадров — через --image. Вход ChatGPT
используется штатный. Сессия исправлений продолжается через exec resume; новая сессия создаётся для другого ролика.
Режиссёр студии сохраняет доступ к подключённым инструментам и правилам проекта.

## Правки за один просмотр

Собери замечания в одно сообщение: «1. В 0:03 слово выше; 2. В 0:12 убрать фото; 3. Музыку тише».
Агент применяет весь список, сохраняет удачную идею и ручные изменения timeline.json, затем один раз пересобирает
и проверяет. Дописанные во время работы сообщения студия собирает в один следующий запрос.
Механические операции не требуют ещё одного вызова ИИ. Большая сессия продолжается свежей с передачей дел.

Старые разговоры Claude доступны для чтения. При первом открытии история сохраняется, для продолжения готовится
передача дел, идентификатор чужой сессии сбрасывается. Следующий запрос идёт в Codex.

## Кэш и честный учёт

Общие инструкции ставим перед меняющимися материалами; исправления продолжают ту же сессию. OpenAI управляет
кэшированием автоматически: «мод подогрева» и периодические пустые запросы здесь не используются. Кэш не заменяет
короткий контекст и не гарантирует попадание. [Документация OpenAI о кэшировании](https://developers.openai.com/api/docs/guides/prompt-caching).

Каждый ход пишет в work/<имя>/analyst.jsonl модель, роль, усилие, входные/выходные/закэшированные токены, секунды
и результаты проверок. Кэш входит во входные токены: при суммировании его не прибавляют второй раз.
Точная цена подписочного хода Codex не сообщается: cost=null; неизвестное не отображается как $0.
Старые долларовые замеры Claude — история в ИЗДЕРЖКИ.md, к GPT их не переносим.

Ни подписка, ни кэш не обещают сотни роликов: расход зависит от модели, длины контекста, инструментов, изображений
и сложности правок. Перед оценкой количества роликов нужен реальный пилот и наблюдение за лимитами.
[Лимиты и расход Codex](https://learn.chatgpt.com/docs/pricing).

## Проверка перехода

selfcheck проверяет команды и роли GPT, продолжение сессий, миграцию истории, обработку JSONL, ошибки и учёт
токенов без обращения к модели. Проверки рендера и памяти сохраняются. Изменения выпускаем после selfcheck,
длинной проверки рендера при его изменении и verify_page --all при изменении страниц/compose/kit.
Отдельно проверяем реальный короткий вызов Codex и приложение изображения: подставной ответ этого не доказывает.
